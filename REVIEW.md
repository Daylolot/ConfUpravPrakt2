# Ревью второй практики, вариант № 9

Проверка выполнена 23 ноября 2026 года по исходному заданию и опубликованным
веткам репозитория. Исправления добавлены отдельными коммитами, история
исходных пяти этапов сохранена.

## Что было исправлено

1. Свойства родителя раскрывались до переопределений дочернего POM.
   Воспроизведение: родитель задаёт lib.version=1.0, ребёнок меняет на 2.0,
   но прежняя программа выбирала 1.0. Теперь выбирается 2.0.
2. Изменение только scope в дочернем POM теряло унаследованную версию.
   Теперь поля декларации объединяются.
3. Добавлен импорт управляемых версий BOM. Он участвует в настройках
   модели, но не становится ребром графа библиотек.
4. Секции с тестовыми зависимостями исключаются из runtime-графа до
   разрешения их версий. Неизвестное свойство неиспользуемой тестовой
   зависимости больше не мешает анализу.
5. Некорректный XML с корнем, отличным от project, теперь отклоняется,
   а не превращается в ложный граф без зависимостей.
6. LATEST и RELEASE отклоняются как плавающие версии.
7. Инструкции исправлены: GitHub содержит ветки origin/stage-N,
   а не метки stage-N. После обычного git clone команды работают.
8. Добавлены реальные Mermaid/ASCII-файлы для трёх пакетов и диаграммы
   в README; тестовое покрытие расширено с 4 до 21 метода.

При проверке порядка Maven запросил JAR JUnit перед JAR Hamcrest.
Наш DFS выдаёт Hamcrest перед JUnit: это корректный порядок готовности
зависимостей, а не воспроизведение сетевого расписания Maven.
Объяснение включено в инструкцию для защиты.

## Границы реализации

Это учебный анализатор объявленных compile/runtime-зависимостей,
а не полная реализация Maven Resolver. Не реализованы профили,
exclusions и стратегия разрешения конфликтов nearest-wins.
Разные версии одного артефакта сохраняются отдельными узлами.
Граф ориентирован на обычные JAR без classifier; неподдерживаемые
выбранные типы или версии приводят к явной ошибке.

Optional-зависимости самого анализируемого пакета показываются, но
optional промежуточных пакетов не распространяются. Сравнение Maven
через проект-обёртку рассматривает выбранный пакет как библиотеку,
поэтому в общем случае его optional-зависимости будут исключены.
Для трёх выбранных демонстрационных пакетов это не меняет граф.

Полная семантика родительских моделей и профилей Maven выходит за
поддержанный поднабор. Для других пакетов совпадение заранее не обещается.
Правила Maven:
https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html
